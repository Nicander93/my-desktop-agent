# DWB v1：36 个 Golden Tasks 任务设计
每个任务均采用公共用户场景。这里定义的是目标、Fixture 和验收边界，不规定 Agent 必须使用 Python、Node、OfficeCLI 或其他具体实现。

# PP · 个人生产力
## PP-001 · Downloads Organizer

**难度：** D2

**用户原始需求**

> 整理杂乱的下载目录，按内容类型分类，识别重复文件，生成操作清单；默认不删除文件。

**Fixture 设计**

- 使用 6–20 个输入文件或一份中等规模结构化数据；
- 至少包含一个正常样例、一个边界样例和一个噪声样例；
- 输入文件名不得出现在参考实现的业务逻辑中；
- 对需要变更文件的任务，保留 baseline 哈希；
- D2/D3 任务至少准备一个不暴露给 Agent 的 hidden fixture。

**预期产物**

- `organized/`
- `manifest.json`
- `duplicates.json`

**核心能力标签**

`filesystem`, `inspect`, `hash`, `plan`, `verify`

**Hard Verifier**

- dry-run 无副作用
- 文件哈希保持
- 无覆盖和删除
- 清单与实际一致

**Trajectory 观察项**

- 是否先检查输入再写入；
- 是否实际运行生成的工具或打开产物进行验证；
- 是否发生重复失败调用、越权写入或修改保护文件；
- 是否对异常输入进行隔离，而不是静默丢弃；
- 最终文本是否准确描述实际产物状态。

**建议诊断子任务**

- D0：仅验证本任务的核心解析或文件操作；
- D1-A：处理单个标准输入；
- D1-B：处理参数变化或异常输入；
- Golden Task 失败后按上述顺序自动回退诊断。
